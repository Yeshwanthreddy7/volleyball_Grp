## Current architecture, in one paragraph

Broadcast video → **preflight gate** (aborts if the surviving player population
is degenerate) → **dual detector** (stock YOLOv11 for players, volleyball
fine-tune for the ball, both at imgsz 1280) → **court calibration** (auto quad
detection, camera-motion compensation, in/out-of-court mask) → **BoT-SORT
tracking** with occlusion-bridged persistent slots → **jersey-colour team
separation** with per-track voting → **18-dim permutation-invariant features**
(`perm_invariant_v2`) → 29-frame windows → **learned classifier** (scikit-learn
by default, Mamba SSM as the deep-learning comparison arm, selected by file
extension) → per-sequence CSV, annotated video, coordination report.

## The three things a reviewer should know

1. **Labels come from a rule engine**, so cross-validation measures agreement
   with a heuristic teacher, not tactical accuracy. `fyp/annotate.py` produces
   the blind human gold set that converts this into a real claim; that
   annotation has not yet been done.

2. **Two evaluation protocols are always reported together** — stratified k-fold
   (within-video, optimistic) and leave-one-video-out (cross-video, honest). The
   gap between them is a result: it quantifies reliance on camera-specific cues.

3. **Every serious failure in this project was silent**, never a crash. The
   pipeline would run to completion and print a formatted tactical report built
   on zero players. That is why `fyp/preflight.py` exists and why the test suite
   replays each historical failure with its real measured values.

## Reproducing everything

```bash
python reproduce.py
```

Writes `results/latest/` with METRICS.md, provenance.json (package versions and
artefact hashes), machine-readable CSVs and all figures. Exits non-zero if any
asserted property fails.
